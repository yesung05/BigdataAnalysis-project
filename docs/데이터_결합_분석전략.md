## 2. 결합 방법 상세

### 레벨 1 — 직접 JOIN (키 존재)

#### 결합 A × C/D: 구급출동 ↔ 소방서 좌표

```python
# 구급출동 CNTR_NM: "고덕119안전센터"
# 소방서 좌표  소방서명: "강동소방서-고덕-119 안전센터"  ← 포맷 불일치!

# 정규화 함수
def normalize_center_name(name: str) -> str:
    name = re.sub(r'소방서[_\-\s]*', '', name)   # 소방서명 제거
    name = re.sub(r'[\s\-_]', '', name)           # 공백·특수문자 제거
    name = name.replace('119안전센터', '').replace('안전센터', '')
    return name.strip()

# 정규화 후 merge
dispatch['cntr_key'] = dispatch['CNTR_NM'].map(normalize_center_name)
station['cntr_key'] = station['소방서명'].map(normalize_center_name)
merged = dispatch.merge(station[['cntr_key', 'X좌표', 'Y좌표', '유형']],
                        on='cntr_key', how='left')
```

**매칭 불가 케이스 처리**: `rapidfuzz` 라이브러리 퍼지매칭 (similarity ≥ 85%)으로 보완.

### 레벨 2 — 집계 수준 결합

#### 결합 A × B: 구급출동 ↔ 구급상황관리 (레코드 직접 Join 불가)

두 테이블 간 공통 고유 키가 없으므로 **지역+날짜 집계 후 비교**:

```python
# 구급출동 집계
dispatch_agg = dispatch.groupby(['GRNDS_CTPV_NM', 'DCLR_YMD']).agg(
    출동건수=('RPTP_NO', 'count'),
    뺑뺑이건수=('TRANS2_RSN', lambda x: x.notna().sum())
).reset_index()

# 구급상황관리 집계
mgmt_agg = mgmt.groupby(['CTPV_NM', 'MDLCR_DSCSN_BGNG_YMD']).agg(
    의료지도건수=('MDLCR_DSCSN_SN', 'count'),
    평균소요시간=('소요시간_분', 'mean')
).reset_index()

# 시도+날짜로 결합
combined = dispatch_agg.merge(
    mgmt_agg,
    left_on=['GRNDS_CTPV_NM', 'DCLR_YMD'],
    right_on=['CTPV_NM', 'MDLCR_DSCSN_BGNG_YMD'],
    how='left'
)
```

#### 결합 A(서울) × E: 구급출동(서울 필터) ↔ 서울 월별 Excel

```python
# 구급출동에서 서울만 추출 후 월 집계
seoul_dispatch = dispatch[dispatch['GRNDS_CTPV_NM'] == '서울특별시'].copy()
seoul_dispatch['월'] = seoul_dispatch['DCLR_YMD'].astype(str).str[4:6].astype(int)
seoul_monthly = seoul_dispatch.groupby(['DCLR_YR', '월']).size().reset_index(name='샘플건수')

# 샘플 비율로 전체 모수 추정: 5000 / 실제연간건수
# Excel 실제 건수와 비교 검증
```

### 레벨 3 — 실시간 결합 (추천 서비스)

추천 서비스 런타임에서만 사용. 분석 DB에 저장하지 않음:

```python
# 사용자 입력: GPS(lat, lon) + 증상
def recommend(lat, lon, symptom):
    # 1. 가장 가까운 안전센터 Top 3 (소방서 좌표 C 기준 Haversine)
    centers = find_nearest_centers(lat, lon, station_df, top_k=3)

    # 2. 증상 기반 병원 E-Gen API 조회
    hospitals = egen_api.query(symptom=symptom, lat=lat, lon=lon)

    # 3. 안전센터 출동 부하 가중치 (분석 결과 A×C 결합 테이블)
    centers['부하지수'] = centers['cntr_key'].map(load_index)

    return centers, hospitals
```

## 3. 도출 가능한 인사이트

### 🔴 우선순위 1 — 뺑뺑이 분석 (프로젝트 핵심)

#### 3-1. 지역별 2차 이송 발생률
- **데이터**: 구급출동 A — `TRANS2_RSN`, `GRNDS_SGG_NM`
- **방법**: `GRNDS_SGG_NM`별 `TRANS2_RSN.notna()` 비율 집계 → 시군구 단위 choropleth 지도
- **예상 결과**: 수도권 외곽·지방 중소도시 거부율↑, 대형병원 밀집 지역↓

#### 3-2. 거부 이유 분류
- **데이터**: `TRANS2_RSN`, `TRANS3_RSN` 텍스트값
- **방법**: 텍스트 기준 카테고리 매핑 → 막대 차트
  ```
  "병상없음" / "만실" → 병상 부족
  "진료불가" / "전문의없음" → 전문성 부재
  "거리" / "이송불가" → 지리적 요인
  ```
- **예상 결과**: 병상 부족이 가장 큰 거부 이유 (선행 연구 기준)

#### 3-3. 뺑뺑이 시 추가 이동 거리 손실
- **데이터**: `GRNDS_DSTNC`(1차 이송거리), `GRNDS2_DSTNC`(2차), `GRNDS3_DSTNC`(3차)
- **방법**: `GRNDS2_DSTNC - GRNDS_DSTNC` → 평균 추가 이동 km 계산
- **예상 결과**: 뺑뺑이 1회당 평균 X km 추가 → 응급환자 생존율 영향 정량화 가능

#### 3-4. 연도별 뺑뺑이 추이 (2017→2022)
- **데이터**: 구급출동 A — `DCLR_YR`, `TRANS2_RSN`
- **방법**: 연도별 2차 이송 발생률 선 그래프
- **예상 결과**: COVID-19 영향(2020~2021) 구간에서 이상치 여부 확인

---

### 🔴 우선순위 1 — 소방서별 출동 부하 지도

- **데이터**: 구급출동 A(`CNTR_NM`) × 소방서 좌표 C/D (퍼지매칭 JOIN)
- **방법**: 안전센터별 연간 구급 출동 건수 집계 → 좌표와 merge → Folium 버블 지도 (크기=출동량)
- **활용**: 추천 서비스에서 "현재 부하가 낮은 안전센터" 우선 추천 가중치 근거

---

### 🟡 우선순위 2 — 증상 기반 분석 (추천 서비스 입력값)

#### 3-5. 증상별 중증도 프로파일 (두 테이블 비교)

| 비교 관점 | 구급출동 A | 구급상황관리 B |
|---------|-----------|-------------|
| 증상 컬럼 | `PTN_SYM_SE_NM` (현장 분류) | `MAIN_SYM_NM` (의료지도 분류) |
| 중증도 | — | `SRIL_CLSF_NM` |
| 결합 방법 | 증상 텍스트 기준 집계 비교 | (별도 집계) |

- **방법**: 두 테이블 각각 증상별 빈도 집계 후 나란히 비교 → 현장 분류와 의료 분류 간 차이 파악
- **활용**: 사용자 입력 증상 → 중증도 예측 → E-Gen API 검색 조건 설정

#### 3-6. 증상별 이송 성공률
- **데이터**: 구급출동 A — `PTN_SYM_SE_NM` × `TRMN_SE_NM`
- **방법**: `TRMN_SE_NM == '이송'` 비율 → 증상별 bar chart
- **예상 결과**: 심정지·호흡정지는 이송률↓ (현장 사망↑), 질병·부상은 이송률↑

---

### 🟡 우선순위 2 — 날씨 × 출동 상관

- **데이터**: 구급출동 A 내장 날씨 컬럼 (`HR_UNIT_ARTMP`, `HR_UNIT_SNWFL` 등)
- **방법**: `DCLR_YMD` 기준 일별 집계 → 날씨 조건 × 출동 건수 scatter + 상관계수
- **가설 검증**:
  - 기온 ≤ -5°C → 심혈관계 출동↑?
  - 폭설 시 → 교통사고 출동↑?
  - 기온 ≥ 35°C → 온열질환 출동↑?

---

### 🟢 우선순위 3 — 시계열 트렌드

#### 3-7. 구급 출동 연도별 추이 (전체 모수 추정)
- **방법**: 샘플 5,000건/년 × (실제 파일 행 수 / 5,000) = 전체 모수 추정
  - 구급출동 실제 행 수는 파일 크기 기준 연간 약 48~62만 건
- **기대 차트**: 2017~2022 막대 + 2022~2024 서울 Excel 연결 선 그래프

#### 3-8. 지역 커버리지 분석
- **데이터**: 소방서 좌표 C + 구급출동 A(`DAMG_RGN_LOT/LAT` 사고 좌표)
- **방법**: 각 사고 지점에서 가장 가까운 안전센터까지 Haversine 거리 계산 → 분포 히스토그램
- **예상 결과**: 대부분 5km 이내, 특정 지역 10km+ 공백 식별 → 추천 서비스 "거리 기반 우선순위" 근거

## 4. 결합 시 핵심 제약사항 및 대응

| 제약 | 원인 | 대응 전략 |
|------|------|---------|
| **시각 정보 100% 결측** | DCLR_TM 등 시분초 컬럼 null | 날짜(YMD) 기반 일별 집계로 전환. 시간대(hourly) 분석 포기 |
| **안전센터명 포맷 불일치** | 데이터 출처별 명칭 규칙 상이 | 정규식으로 핵심어 추출 + `rapidfuzz` 퍼지매칭 (threshold 85%) |
| **상황관리 결측 66~77%** | 수집 체계 미비 | `dropna` 후 유효 25~35%만 사용. 분석 결과에 편향 주의사항 명시 |
| **A↔B 직접 키 없음** | 설계 상 별도 DB | 지역+날짜 집계 수준 결합. 레코드 수준 매칭 불가 |
| **이송 병원명 없음** | 미기록 | E-Gen API 실시간 조회로 대체. 이력 기반 분석은 불가 |
| **대용량 (1.3GB+)** | 파일당 200~300MB | Parquet 변환 캐시, 청크 처리, 서울 필터 후 분석 |

## 6. 추천 서비스 데이터 흐름 (최종 목표)

```
사용자 입력
  ├── GPS 좌표 (lat, lon)
  └── 증상 선택

        ▼

분석 완료 데이터 (오프라인 사전 계산)
  ├── 안전센터 좌표 테이블 (A×C JOIN 결과, Parquet)
  │     columns: cntr_nm, lat, lon, 연간출동건수, 부하지수
  └── 증상→중증도 매핑 테이블 (A+B 집계 결과)
        columns: 증상, 중증도예측, 이송성공률

        ▼

실시간 계산
  ├── Haversine으로 안전센터 거리 정렬 → Top 3
  ├── 부하지수 가중치 적용
  └── E-Gen API: 증상+위치 → 수용 가능 병원 조회

        ▼

출력
  ├── 추천 119 안전센터 (거리 + 부하 기반)
  └── 추천 병원 (병상 여유 + 거리 + 전문과목 기반)
```
